# README critic: README.md

This README fails the minimum: 4 thing(s) a reader needs are missing or broken. It is not ready to be someone's first impression.

## Failures (minimum not met)
- [RM-TITLE] It does not open with a title. (the first line is not a level-one title)
- [RM-ONELINER] It never says what the project is in one plain sentence. (there is no sentence under the title)
- [RM-LICENSE] A reader cannot tell whether they may use it. (no License section)
- [RM-LIMITS] It reads as a brochure: no limits are admitted. (nowhere does it say what the project will not do)

## Gaps (not strong)
- [RM-SUPPORT] A stuck reader has nowhere to go. (no place to ask for help)
- [RM-TOC] It is long and offers no way through. (132 lines and no table of contents)
- [RM-EXAMPLES] No example a reader can run. (no runnable examples are linked)

## Not over the top
- [OT-QUICKLINKS] There is no way to jump to what you came for. (fewer than three navigation links in the first screen)
- [OT-BADGES] No badge tells the reader anything. (no badge in the first screen (CI status, license or version tells a reader something real))
- [OT-ARCH] A contributor cannot see how it fits together. (no architecture or how-it-works section)
- [OT-FAQ] The obvious questions go unanswered. (no FAQ)
- [OT-ALTERNATIVES] It does not say why this and not something else. (no comparison with alternatives)
- [OT-ROADMAP] It does not say where it is going. (no roadmap, so the reader cannot tell where it is going)
- [OT-DECISIONS] The reasoning behind the design is not written down. (no link to why the design is the way it is)

## What holds
- RM-INSTALL Install, with a command
- RM-USAGE Usage, with a code block
- RM-LINKS No broken relative links
- RM-SIZE Under GitHub's size limit
- RM-CONTRIB Contributing, with a stance
- RM-STATUS Project status
- RM-FENCES Code blocks name their language
- OT-VISUAL A picture of the thing
- OT-DEMO A demo with its output
- OT-EVIDENCE Claims come with their evidence
